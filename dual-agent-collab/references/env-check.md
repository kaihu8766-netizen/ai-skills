# 环境自检清单（env-check.md）

装好 dual-agent-collab 后 1 分钟自查，确认"降级门禁"真的生效（C 档配套，防再次踩"静默降级"坑）。

## 1. key 入口探测
- [ ] 环境是否可注入 `DEEPSEEK_API_KEY`？（环境变量前缀调用 / 会话内可向用户索取 / 受控配置文件）
- [ ] deps.md 的三类入口，当前环境支持哪类？写进本环境备注

## 2. 降级声明生效测试（关键）
- [ ] 模拟无 key 场景（不设环境变量）启动一个任务 → 执行 Agent 是否**先单独询问用户并等待裁决**（A 提供 key / B 同意降级 / C 跳过）？
- [ ] 是否出现"未询问即自行降级 / 交付说明小字标注"？→ 出现即 FAIL，技能未生效，重装后重测

## 3. 受控通道正常（有 key 时）
- [ ] `DEEPSEEK_API_KEY=<key> python3 scripts/deepseek_review.py --topic "RV-自检" --prompt "…结论三态…"` 跑通，输出 RV 号
- [ ] 原始请求/响应落盘（raw/ 或 collab-archive/）存在

## 4. 降级记录落盘
- [ ] 发生降级后，档案出现 `status=degraded` + 用户同意记录（light-archive.md 降级记录字段）
- [ ] 无用户同意 → 该档案视为无效，需补

## 5. 路由表核对
- [ ] 重大/不可逆/对外交付类任务，在无独立复核时是否 BLOCKED 上报（而不是降级继续）？
- [ ] 琐事/纯查询在无 key 时是否走"跳过评审"而非"子代理评审"？

## 判定
- 5 项全过 → 环境达标，可正常使用双 Agent 协作
- 任一 FAIL → 先修技能安装/配置，不要带病开工
