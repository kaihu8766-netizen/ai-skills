# 门禁与闸门（gates.md）

两层强制：**Git 提交门禁**（机器强制，防漏评审）+ **讨论闸门**（周期任务/定时任务触发条件）。

## Git 提交门禁（commit-msg 钩子，可选但强烈建议）

在 Git 仓库 `.githooks/commit-msg` 安装，`git config core.hooksPath .githooks`。三闸门：

1. **闸门 1（ID 引用存在性）**：提交信息必须含合法 ID 引用（`RV-*` / `F-*` / `D-*` / `ISS-*`）→ 防止"未评审的提交"
2. **闸门 2（红线 diff_hash 匹配，机器规则）**：命中红线文件（核心代码/脚本/规则）的提交，必须引用**已批准（adopted）且 diff_hash 与当前 staged diff 一致**的 RV，否则拒绝 → 防止"后补评审"
   - 实现提示：提交前计算 staged 文件的 sha256，写入评审档案；钩子对比当前 staged hash 与档案 hash
3. **闸门 3（功能提交需事前对齐）**：功能提交（`feat(` 开头）必须引用已批准（adopted）的 **scheme 通道 RV**（phase=scheme 且 feature 匹配）→ 防止"没讨论就动手"

**轻量通道（[LIGHT]）**：非功能、非红线的小改动（文案/样式等）可免 scheme 评审，但提交仍需引用已 adopted 的 RV 或走白名单判定。**限额与判定规则必须写在脚本里（gate_rules.yaml），不能靠自觉；技能不复制限额数字（防止与实现漂移），以 gate_rules.yaml 为唯一真源。**参考实现限额（invoice-precheck gate_rules.yaml）：≤3 文件 / ≤30 行 / 单行 ≤500 字符 / 7 天 ≤50 行 / **7 天 ≤5 次 LIGHT 提交**；白名单仅 `*.md` 与 `docs/index.html`（且 index.html 限定"非 demo_data 段 + 非 script 区间"的文案/样式改动）。

## 讨论闸门规则（周期自检/定时任务触发时）

按七段执行（比"四条"更完整的实战抽象）：

1. **判定三态**：纯只读且与上次基线完全一致 → 免讨论，记录"无异常"；有状态变化/异常/需决策 → **必须**先与 DeepSeek 讨论（review 通道，落盘）→ 有结论再行动；无法判定 → fail-closed 视为需讨论
2. **基线**：以最近一次成功运行的记录为基线，增量比较；不按"当天"而按"自上次基线以来的增量"
3. **动作约束**：讨论结论为拒绝或条件未落实 → 不得执行该动作
4. **紧急止损白名单**：仅限数据泄露止损/环境故障/安全事件三类可先止损后 24h 内补讨论；止损前留脱敏证据；跨仓改动需例外条款
5. **降级禁止 fail-open**：DeepSeek 不可用时不可逆动作 BLOCKED 上报用户，禁止擅自继续
6. **记录**：每次讨论/自检结果落 DailySummary（问题清单、DeepSeek 意见、待拍板项）
7. **诚实边界**：机制"防遗忘不防恶意绕过"——纪律依赖执行者诚实遵守

## 失败与回滚

- 评审发现致命错误：先修复再提交；已提交的用 `git revert`/`git reset` 回退，回退本身也要引用 RV 留痕
- commit 已过三闸门但事后发现错误：按新 RV 记录缺陷 → 修复 → 重审 → 新提交；**不修改历史 commit**
- 回滚优先级：可逆（代码/文档）→ 立即回滚；不可逆（已发布/已外发）→ 上报人类决策

## 常见坑（实战教训）

- **adopt 追加新序号 ≠ 原 RV 号**：索引按 topic 追加行时，同 RV 会出现多行；钩子按"序号前缀"匹配会取错行 → 钩子应改按**档案 frontmatter 的 RV id 精确匹配**，索引清理冗余行时保留 adopted 行
- **钩子与档案 hash 算法不一致**（排除集/路径不同）→ 同一 diff 两边算出的 hash 不同 → 校验必失败；两边必须共用同一份 EXCLUDE/路径规则
- **索引只追加不删**，但冗余 pending 行会造成误判 → 定期归并（删 pending 冗余、保留 adopted）
- **评审 Agent 无联网**：需要联网核实的事实由主 Agent 先查证后喂给评审，评审只做推理与结构性审查
- **长上下文截断**：评审材料超长时拆段，或只发关键 diff 摘要
- **评审链断点（白名单）**：评审 Agent 只读范围受白名单仓库限制——**技能仓/未挂载路径不可读**；需要评审技能自身或仓外对象时，先把对象镜像进白名单仓（如 `skills-mirror/`）或直接贴进 prompt
