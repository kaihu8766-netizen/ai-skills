# 联网取证流程（research.md）

**为什么必须联网取证**：DeepSeek 无联网能力，它只能基于你喂给它的证据做判断；而主 Agent 的记忆可能过时或出错。关键事实不验证 = 交付物可能建立在幻觉上。这是"靠谱"的核心纪律（v2 用户拍板：关键事实强制验证）。

## 一、事实点拆解（动手前）

把任务拆成**需要验证的事实点清单**，标注类型与风险：

- **硬事实**：人名/头衔/公司/日期/数字/价格/政策/版本号 → 必须联网验证
- **软事实**：行业趋势/普遍做法/个人经历 → 尽量找来源；找不到标注"基于经验判断"
- **观点**：评价/建议 → 无需验证，但应区分"事实 vs 观点"

## 二、来源分级（交叉验证的依据）

| 等级 | 来源类型 | 可信度 | 使用方式 |
|---|---|---|---|
| S | 官方（政府/官网/官方文档/学术期刊） | 高 | 可直接作为证据 |
| A | 权威媒体/知名机构/数据库 | 较高 | 可引用；重大结论建议双源 |
| B | 一般媒体/行业网站/社区/论坛 | 中 | 用于参考；标注来源 |
| C | 个人博客/社交媒体/未知来源 | 低 | 仅作线索，不作为结论依据 |

**时效检查**：政策/价格/版本/新闻类事实必须确认"信息仍是当前有效"（发布时间近于合理周期）；过时来源要标注时间。

## 三、搜索与取证工具选择

| 需求 | 工具 |
|---|---|
| 通用信息/关键词调研 | 通用搜索（拆多个关键词并行） |
| 网页/文档/PDF 全文 | 网页抓取（分页读全文，长文档读完） |
| 图片/实体识别 | 图片搜索（仅真实实体，不搜抽象概念） |
| 特定平台（小红书/微博/B站/淘宝等） | 按平台专用 Skill 或浏览器流程 |
| 学术论文 | 学术搜索 |

**取证记录**：每次搜索记录 来源URL + 关键片段（用于喂 DeepSeek 和交付引用）。

## 四、交叉验证（喂给 DeepSeek 的格式）

DeepSeek 无联网 → 把**搜索结果原文片段**贴进评审 prompt（不是只贴结论）：

```text
【证据（来源原文片段）】
来源：https://xxx（S 级官方，2026-09 发布）
原文："…关键内容…"
【我的解读】…（可标注省略了哪些部分）
【待验证问题】1) 该事实是否支撑结论 2) 有无更权威反证
```

规则（反选择性举证）：贴原文片段 + 行号/段落，摘要仅作背景并声明省略了什么。

## 五、交付物引用格式

- 关键结论后附来源：`（来源：<URL>）` 或脚注
- 区分"已查证"（有 S/A 级来源）与"一方称/待核实"（B 级以下或单源）
- 搜不到的事实：标注"未查到公开来源"，不编造
