# 双 Agent 协作模式（通用版 v2）

**一句话**：让"执行 + 独立复核 + 人类裁决"成为任何任务的默认工作方式——干活有讨论、结论有复核、事实有来源、过程有留痕。

## 角色

| 角色 | 职责 |
|---|---|
| 主 Agent（本 Agent） | 干活（执行任务）；**联网搜索取证**（DeepSeek 无联网，信息获取是主 Agent 的职责）；发起讨论与复核；维护轻量档案 |
| DeepSeek（评审 Agent） | 独立评审/讨论（不参与执行，避免自我确认偏差）；做**事实交叉验证**、质量把关、找漏洞；给出结论 |
| 人类（用户） | 最终裁决；拍板重大决策（拍板选项自带收益评估）；提供目标与边界 |

## 任务路由表（先查这张表，决定要不要讨论/复核）

| 任务类型 | 事前讨论 | 事后复核 | 说明 |
|---|---|---|---|
| **重大/不可逆/对外交付**（简历定稿、正式文档、发布、承诺、花钱决策） | **必须** | **必须** | 不可逆动作人不在时 BLOCKED 上报 |
| **功能性工作**（方案初稿、写作、邮件、分析、设计） | 建议（快速对齐：目标+关键取舍一句话给 DeepSeek） | 必须 | 复核重点：质量+遗漏+事实 |
| **日常搜索/调研/信息收集** | 不讨论 | **关键事实交叉验证** | 结论靠证据链不靠记忆 |
| **琐事/纯查询**（查定义、确认小事实） | 跳过 | 跳过 | 但引用的关键事实仍须有来源 |

## 核心流程（5 步）

1. **拆解任务**：目标、范围、交付物、关键事实点（哪些事实必须联网验证）
2. **事前对齐**（按路由表）：动手前把方案（目标/关键取舍/风险）发给 DeepSeek 讨论 → 通过/有条件通过才动手；拒绝则改方案
3. **执行 + 联网取证**：主 Agent 干活；关键事实用搜索工具验证（见 references/research.md——来源分级、交叉验证、引用格式）
4. **事后复核**（按路由表）：DeepSeek 独立检查成果（事实核查/质量/遗漏/反证）→ 通过才交付；拒绝则修复重审
5. **交付 + 落档案**：交付物给用户；任务记录存轻量档案（见 references/light-archive.md——无 git 仓库自动存主 Agent 工作区）

## 讨论纪律（不可谈判）

- 结论三态：`通过` / `有条件通过`（列出条件）/ `拒绝`（列出原因）；拒绝或条件未落实 → **不得执行该动作**，上报用户
- 评审必须落盘（原始请求/响应 + 结论），供事后审计
- **收益评估前置**：向用户提出拍板选项时，同步附上每个选项的收益/影响评估
- 触发条件：红线/不可逆/对外交付类 + 用户明确说"讨论"的任何改动，不可跳过

## 联网取证（强制纪律）

- **DeepSeek 无联网**——一切外部信息（人名/数据/政策/价格/新闻/行情）必须由主 Agent 搜索获取，把**搜索结果原文片段**喂给 DeepSeek 做交叉验证
- **禁止用记忆编造事实**：拿不准的事实必须搜；搜不到标注"未查到"而不是编
- 交付物中关键结论附**来源 URL**（来源分级与引用规范见 references/research.md）

## 快速开始（示例：做简历）

```bash
DEEPSEEK_API_KEY=<key> python3 scripts/deepseek_review.py \
  --topic "RV-YYYYMMDD-NN-简历方案讨论" \
  --prompt "【方案讨论】我要做一份前端岗简历，目标岗位/经历/亮点如下：…。请评审：1) 结构是否抓住招聘方重点 2) 经历表述有无可优化点 3) 有无遗漏的关键模块。结论：通过/有条件通过/拒绝。" \
  --max-tokens 2500
```

流程：讨论方案 → 主 Agent 写简历 → DeepSeek 复核（事实核查：公司名/时间线/数据是否正确）→ 交付 + 存档案。

## 可选高级模式（有 git 仓库的项目）

企业级门禁（commit-msg 钩子强制未评审提交被拒、索引/RV/双 hash 档案）见 [references/gates.md](references/gates.md)——`scripts/install-gate.sh <项目根>` 一键装。**无仓库时**：靠"讨论纪律 + 轻量档案留痕"兜底（fail-closed 语义：讨论不是可选项，档案可审计）。
